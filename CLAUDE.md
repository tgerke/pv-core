# pv-core

Sponsor/CRO-side pharmacovigilance safety database for clinical trials. Compliance
(21 CFR Part 11) is enforced in the Postgres schema (triggers, immutability, version
locking, hash-chained audit), not in app code. Design docs in `docs/`, decision log in
`docs/decisions/` (read the ADRs before changing anything they cover).

## Commands

```sh
pnpm db:up && pnpm db:migrate && pnpm db:seed && pnpm dev   # full stack
pnpm test                    # vitest, needs Postgres (MinIO for the s3 storage test)
pnpm check                   # lint + typecheck + test
pnpm db:import-meddra -- --version 27.1 --dir /path/to/ascii   # licensed MedDRA, verbatim (ADR-0005)
pnpm digest                  # reminders digest email per study (ADR-0014)
pnpm validation:iq           # installation qualification vs the live env (ADR-0017)
pnpm validation:artifacts    # OQ report + traceability matrix (runs the suite)
```

API :8789, web :5176, Postgres :5436, MinIO :9002 (console :9003), mailpit SMTP :1026 /
UI :8026 (docker compose). Sibling stacks keep their own ports (edc 5432, ctms 5433,
dmops 5434, rtsm 5435).

## Constraints that will bite you

- `.env` must set `AUTH_MODE` (`dev` or `oidc`); the API refuses to boot without it. Dev
  tokens `dev-admin-token` / `dev-processor-token` / `dev-reviewer-token` /
  `dev-readonly-token` / `dev-ingest-token` map to seeded people by email. The reviewer
  and processor are sponsor-scoped (they never see the second sponsor's cases); the
  ingest token is enter-only and reads nothing (403 on every GET).
- Re-seeding regenerates all UUIDs; never cache ids across seeds. `pnpm db:seed` truncates;
  never run it against a real deployment.
- Signatures, submissions, acknowledgements, attachments, and the case facts are immutable
  at the DB level, and a case version locks at its first signature (ADR-0006), so tests
  cannot clean up after themselves. Tests create their own cases under the fixture study
  `CORC-9999`; reset demo state with `pnpm db:seed`.
- The API always connects as the DML-only `pv_app` role (migration 0002). If a runtime
  query needs DDL or TRUNCATE, the design is wrong.
- Every audited write goes through `withActor()`; a write outside it is attributed to
  `system`, which is a bug everywhere except migrations, the importer, and the seed.
- Signing requires `reauth_token` in the request body (§11.200); keep every documented sign
  example consistent with this.
- Regulatory clocks are calendar days in `PV_TIMEZONE`; every connection pins its session
  time zone. Day zero is `case_version.awareness_date`; a value that differs from the
  receipt date needs `awareness_rationale` (CHECK).
- `pv_sync_expected_submissions()` is called by core inside the writing transaction, not by
  a trigger. A new write path that touches a version or its children must call
  `syncVersion(tx, versionId)` or the clock goes stale.
- Arms at rest live only in `case_unblinding` (ADR-0008). Any new view that joins it needs
  review for blind leakage; `pv_readonly` cannot read the arm columns.

## LLM-practice rules (these are logged ADRs, not preferences)

- **Never generate MedDRA content from model memory** (ADR-0005). The importer loads the
  licensed ASCII distribution verbatim; the seed's dictionary is a labeled illustrative
  subset with synthetic codes and never claims to be MedDRA.
- **Never write regulatory specifics from model memory** (ADR-0010). Any ICH E2A / E2B(R3)
  / E2F, 21 CFR Part 11 or 312.32, Regulation (EU) 536/2014, or GAMP 5 claim in docs, ADRs,
  migration comments, or test names must be verified against the full texts in
  `~/Documents/gh-mskcc/clinical-standards-library/sources/` (the distilled reference is
  `~/.claude/skills/clinical-regs/references/ich-e2-pharmacovigilance.md`), citing the
  section. Texts not in that library (21 CFR 312.32, the CIOMS I form, FDA Form 3500A) are
  cited to their authoritative public source with an access date. E2B code lists beyond
  those the reference quotes are grepped from the IG source before they become enums.
- **Never hand-edit `docs/validation/`** (ADR-0017); those files are generated by
  `pnpm validation:artifacts` / `validation:iq` from live runs.
- Compliance claims in docs must never run ahead of the code. When a control ships, update
  `docs/03-compliance.md` and its mirror `site/src/content/docs/compliance.md` together, and
  keep the "honest gaps" list honest.
- Sibling repositories (edc-core, ctms-core, rtsm-core, dmops-core) are prior art: port
  patterns, never share code. Integration is plain HTTP against documented APIs.

## Docs

`docs/*.md` and the site pages in `site/src/content/docs/` deliberately overlap and are
written in the same commit as the feature they describe (ADR-0011); a change to one
usually needs the other. The site is Astro Starlight: `pnpm --filter site dev` to preview,
`pnpm --filter site build` to build (`site/dist/` is gitignored; the build fails on broken
internal links).
